## Before you start — one-time setup (5 minutes)

**These steps must happen in order. If you skip any of them, the app will silently break for every user — not just you.**

- [ ] 1. Open Terminal (press Cmd+Space, type "Terminal", hit Enter)
- [ ] 2. Type this and press Enter:
  ```
  cd ~/Desktop/LadderApp
  ```
- [ ] 3. Push the three new database migrations to your Supabase project:
  ```
  npx supabase db push
  ```
  You should see: output ending with `Finished supabase db push.`
  If you see an error: copy it and tell me — do not continue.

- [ ] 4. **CRITICAL — if you skip this, the entire app goes dark for every user:**

  Go to your [Supabase dashboard](https://app.supabase.com) → select your Ladder project → **Settings** → **API** → scroll to **"Extra options"** → find the field labeled `PGRST_DB_PRE_REQUEST` → set its value to exactly:
  ```
  app.bind_session
  ```
  Click Save. Wait 30 seconds for it to take effect.

  How to confirm it worked: in the Supabase dashboard, go to **SQL Editor** and run:
  ```sql
  SELECT current_setting('app.role', true);
  ```
  If it returns a value (even `null`) without erroring, the hook is active.

- [ ] 5. Deploy the six Edge Functions (run each line, press Enter after each):
  ```
  npx supabase functions deploy ai-gateway
  npx supabase functions deploy founder-login
  npx supabase functions deploy invite-redeem
  npx supabase functions deploy bootstrap-user
  npx supabase functions deploy counselor-invite
  npx supabase functions deploy varun-validate
  ```
  You should see: `Deployed Function <name>` for each one.

- [ ] 6. Enroll the founder TOTP vault secret (one-time, first-time setup only). In Terminal:
  ```
  openssl rand -hex 32
  ```
  Copy the 64-character string that prints out. Then go to your Supabase dashboard → **Settings** → **Vault** → **New secret** → name it `founder_signing_key` → paste the value → Save.

- [ ] 7. Open `LadderApp.xcodeproj` in Xcode (double-click it from Finder at `~/Desktop/LadderApp/`). Press the **Play button (triangle)** to build and run on an iPhone simulator.

  You should see: a screen with the Ladder logo and a "Get started" or "Sign up" button.

  If Xcode shows a red build error: copy the error message from the bottom of the screen and tell me.

## Test 1 — Student signup and first look (8 minutes)

**What we're checking:** that a brand-new student can create an account, land on their dashboard, and see SIA's opening message.

**Why this matters:** this is the first thing every student who downloads the app will experience. If it feels clunky or cold, they'll leave.

**Steps:**

- [ ] 1. On the landing screen, tap **"Sign up"** (or "Get started")
- [ ] 2. Fill in a test email (`student-test@ladder.test` works) and a password with at least 8 characters. Tap **"Create account"**
- [ ] 3. You should see: a short onboarding or a student dashboard with at least 5 tabs along the bottom (Home, Tasks, Colleges, Advisor, Profile — or similar)
- [ ] 4. Tap the **Advisor** tab (the chat or robot icon)
- [ ] 5. You should see: a welcome message from SIA — a few sentences greeting the student and asking something about them. It should NOT be blank or say "Loading..."
- [ ] 6. If you see an error message or a blank screen: tell me the exact text shown

**Things to judge (only you can answer these):**
- Read SIA's opening message. Does it sound warm and human — like a knowledgeable older sibling — or does it sound like a chatbot form letter?
- Does the sign-up form feel obvious? Would a 16-year-old know what to do on it?
- Is there anything on the dashboard that feels missing or confusing for a first-time student?

## Test 2 — SIA conversation and streaming (5 minutes)

**What we're checking:** that sending a message to SIA works, that the response streams in word-by-word rather than appearing all at once after a long wait, and that the timeout is handled gracefully.

**Why this matters:** the streaming feel is the "wow" moment. If it freezes for 4 seconds then dumps text, it feels broken. Word-by-word streaming makes it feel alive.

**Steps:**

- [ ] 1. In the Advisor (SIA) chat screen, type: `hi` and tap Send
- [ ] 2. Watch how the response arrives. You should see: words appearing one by one or in small groups — a "typing" feel — NOT 4 seconds of silence followed by the full response
- [ ] 3. Send a second message: `I'm a junior and I want to study medicine. What should I be doing right now?`
- [ ] 4. You should see: a response that references medicine specifically — not a generic list. It should feel personalized
- [ ] 5. Now turn on **Airplane Mode** on your device (Settings → Airplane Mode ON). Wait 30 seconds. Then send another message in the chat
- [ ] 6. You should see: a clear error message like "Request timed out" or "Check your connection" — NOT a spinning wheel that never resolves. Turn Airplane Mode back off.

**If at step 2 you get a 400 error or the message never sends:** this is a known critical bug (B-03 / S1-CR1). Tell me and I'll route to the debugger immediately — do not continue this test.

**Things to judge:**
- Does the streaming feel fast enough, or does each word take too long to appear?
- Does the medicine response feel like real college counseling advice, or does it feel like it was written for any generic student?

## Test 3 — Career quiz (5 minutes)

**What we're checking:** that all 12 quiz questions appear, that the student can answer them, and that a result is shown at the end.

**Why this matters:** the career quiz is the first personalization signal SIA gets. If it breaks or locks up, the entire personalized experience never starts.

**Steps:**

- [ ] 1. From the student dashboard, find and tap **Career Quiz** (may be under the Home tab or a separate menu)
- [ ] 2. You should see: the first quiz question with multiple answer buttons below it
- [ ] 3. Tap any answer. You should see: the next question appear — NOT a blank screen or a stuck spinner
- [ ] 4. Continue answering until you reach the end. You should see approximately 12 questions total
- [ ] 5. After the last question, you should see: a result screen showing a career path or recommendation (e.g., "Medical", "STEM", "Business")
- [ ] 6. If any question shows zero answer buttons, or the quiz freezes after any answer: tell me which question number it happened on

**Things to judge:**
- Read the quiz questions. Do they feel age-appropriate for a 16- or 17-year-old? Are they too academic, too simple, or about right?
- Does the result feel like something meaningful, or does it feel random?

## Test 4 — Schedule builder (5 minutes)

**What we're checking:** that a student can pick 7 classes, submit the schedule, and that it saves.

**Why this matters:** the schedule builder is how counselors see what students are planning. If it silently drops the submission, counselors are flying blind.

**Steps:**

- [ ] 1. From the student dashboard, find and tap **Schedule Builder** or **My Classes**
- [ ] 2. You should see: a list of class periods (Period 1 through Period 7) that you can tap
- [ ] 3. Tap each period and select a class from the list that appears. Do this for all 7 periods
- [ ] 4. Once all 7 are selected, tap **Submit** (or "Save schedule")
- [ ] 5. You should see: a confirmation message or a green checkmark — something that clearly says the schedule was saved
- [ ] 6. Close the app entirely (swipe it away from the task switcher). Reopen it and go back to Schedule Builder. You should see: the same 7 classes you picked — NOT a blank slate

**If at step 3 you cannot tap a period (no tap response, no class picker opens):** this is a known bug (B-04). Tell me and skip to Test 5.

**Things to judge:**
- Does the class picker feel easy to use? Would a student naturally know how to select their classes?

## Test 5 — Sign out and sign back in as a different student (5 minutes)

**What we're checking:** that when you sign out and sign in as a different student, you see absolutely no trace of the first student's data. This is both a privacy test and a trust test.

**Why this matters (CRITICAL):** if Student A's essays, chat history, or grades bleed into Student B's session, that is a FERPA violation. This test must pass before launch.

**Steps:**

- [ ] 1. While still signed in as your test student, go to **Profile** → **Sign out**
- [ ] 2. You should see: the landing screen or login screen — NOT the student dashboard
- [ ] 3. Sign in as a completely different student account (use a second test email you have)
- [ ] 4. You should see: a fresh dashboard with no data from the first account. Specifically check:
   - The Advisor (SIA) chat history should be empty or show only this new student's messages
   - Any grades, classes, or career quiz results should belong to this student only
- [ ] 5. Go to the Advisor tab. You should see: SIA's fresh opening message with no reference to anything the first student said
- [ ] 6. If you see any data that belongs to the first student: stop this test, take a screenshot, and tell me immediately — this is a launch blocker

**Things to judge:**
- Does the sign-out and sign-back-in feel snappy (under 2 seconds), or does it feel laggy?

- [ ] 3. You should NOT see: fake names like "Maya" or "Noah", mock grade data, or any obviously fabricated student information
- [ ] 4. If you see mock data: screenshot it and tell me (this is bug C4 from the audit)

**Things to judge:**
- Does the "coming soon" screen feel like a thoughtful placeholder — like it was designed — or does it look like a bug?

## Test 7 — Counselor invite and student summary (10 minutes)

**What we're checking:** that a counselor can invite a student, the student receives the invite, and the counselor sees the student's SIA summary — but NOT their raw chat messages.

**Why this matters:** this is the D-002 privacy boundary. Counselors are supposed to see "what does this student need" without reading every word of the student's private conversations with SIA. If this leaks raw chat, that is a privacy violation.

**Steps:**

- [ ] 1. Sign in as a Counselor role account (or create one if you have a school-tenant test setup)
- [ ] 2. Find the **Invite Codes** section in the counselor dashboard. Generate an invite code by tapping "Generate new code" or similar
- [ ] 3. You should see: an invite code appear on screen (a short string or link). You should NOT see a spinning wheel that never resolves
- [ ] 4. Use that code to add a student to the counselor's roster (sign in as the student from Test 1 and redeem the code from their Profile or Settings)
- [ ] 5. Go back to the counselor view. Tap on the student in the student queue or list
- [ ] 6. You should see: a summary card showing things like "currently working on: [topic]", a last-active timestamp, and an "Ask SIA" button. You should NOT see: the student's full chat transcript

**If the invite code is rejected when the student tries to redeem it:** this is a critical bug (B-01/B-02). Tell me the exact error message shown.

**Things to judge:**
- Does the SIA student summary feel useful to a counselor? Would it help them prepare for a check-in conversation?
- Is the "Ask SIA" button visible and clearly labeled?

## Test 8 — Founder login with TOTP (10 minutes)

**What we're checking:** that founder login requires both a password AND a 6-digit TOTP code, that lockout triggers after repeated wrong codes, and that the login feels professional.

**Why this matters:** founder accounts have access to feature flags, school management, and audit logs. Two-factor auth is non-negotiable. If it feels janky, early enterprise customers will not trust the product.

**Steps:**

- [ ] 1. Sign out. On the login screen, long-press the Ladder logo for 5 seconds. You should see: a choice screen asking "Founder" or "Employee"
- [ ] 2. Tap **Founder**. You should see: a login screen asking for email and password
- [ ] 3. Enter your founder credentials and tap Login. You should see: a second screen asking for a 6-digit code from your authenticator app
- [ ] 4. Open your authenticator app (Google Authenticator or Authy) and enter the current 6-digit code. You should see: the Founder dashboard — a screen distinct from the student dashboard
- [ ] 5. Sign out. Repeat steps 1-3, but this time enter the WRONG 6-digit code (type `000000`). Do this twice in a row
- [ ] 6. You should see: after the second or third wrong attempt, a message saying your account is temporarily locked — something like "Too many attempts, try again in 15 minutes." You should NOT be allowed into the founder dashboard

**Things to judge:**
- Does the two-step login flow feel professional? Would a bank or enterprise software feel similar?
- Is it obvious what you're supposed to do at each step, or is there any confusing moment where you weren't sure what to enter?
- Does the lockout message feel clear and reassuring (not alarming)?

## Test 9 — Task switcher privacy (2 minutes)

**What we're checking:** that when you open SIA and then press the Home button to switch apps, the SIA chat content is blurred or hidden in the iOS task switcher — not readable.

**Why this matters:** if a student's private counseling chat with SIA is visible in the task switcher, anyone who picks up their phone can read it. This is an iOS privacy requirement.

**Steps:**

- [ ] 1. Sign in as a student. Navigate to the SIA chat. Type a message like "I'm struggling with math" so there is visible text on screen
- [ ] 2. Press the Home button (or swipe up) to go to the iOS task switcher WITHOUT closing the app
- [ ] 3. Find the Ladder app card in the task switcher
- [ ] 4. You should see: the Ladder app card is blurred or replaced with a generic screen — you should NOT be able to read the chat messages through the task switcher thumbnail
- [ ] 5. If you CAN read the chat messages in the task switcher: screenshot it and tell me (this is security finding S3-1 / S2-CR2 from the audit)
